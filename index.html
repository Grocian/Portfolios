01About

Engineer at the intersection of AI and data.

I design and build the systems that give large language models the right context at the right time: pipelines that turn raw documents and events into clean, structured data, platforms that keep that data trustworthy, and MCP servers that let AI assistants use it safely.

I care most about the unglamorous parts that make AI products work in production — schemas and contracts, evaluation, observability, cost control, and access boundaries. I prefer simple architectures, well-tested code, and documentation the next engineer will thank me for.

01 AI Pipeline

LLM Document Intelligence Pipeline

An end-to-end pipeline that turns unstructured documents — PDFs, emails, and web pages — into validated, structured data and searchable embeddings. Built to run unattended: every stage is idempotent, observable, and covered by automated evaluations.

ingest→ parse & chunk→ llm extract→ validate→ embed→ index

View on GitHub

Highlights

  • Schema-first extraction — LLM outputs are validated against typed models and retried with targeted feedback when they fail.
  • Evaluation harness with golden datasets that tracks accuracy, latency, and cost per document on every change.
  • Resumable batch and streaming modes with deduplication, backoff, and dead-letter handling.
  • End-to-end tracing of prompts, responses, and token spend for debugging and cost control.

02 MCP Server

MCP Server for Internal Data & Tools

A Model Context Protocol server that gives AI assistants like Claude safe, structured access to internal data — warehouse tables, documentation, and operational tools — without handing over raw credentials or unrestricted SQL.

assistant→ mcp client→ tools · resources→ policy layer→ data sources

View on GitHub

Highlights

  • Typed tools with JSON Schema inputs, plus resources and prompt templates for common workflows.
  • Guardrails built in: read-only query validation, row limits, timeouts, and per-user permissions.
  • OAuth-based authentication and an audit log entry for every tool call.
  • Runs locally over stdio or remotely over Streamable HTTP, packaged as a single container.
